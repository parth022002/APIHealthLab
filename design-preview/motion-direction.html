The method

Every result should have a reason.

API HealthLab connects each bounded test to observable evidence and a clear next action. The interface follows that sequence instead of hiding it behind a single green check.

01 · Choose intent

Select the exact API action before entering the credential.

02 · Check policy

Review the execution mode, risk, side effects and possible cost.

03 · Run bounded probe

Execute only a supported test through the controlled network boundary.

04 · Explain evidence

Understand the classified outcome, its limits and what to do next.

Built around trust

Clarity about where tests run.

Security is not an animated badge. It is a set of explicit boundaries, simple language and safe defaults.

Local-first execution

The CLI is the high-assurance path for sensitive credentials. The shared diagnostic core runs locally, keeping those credentials out of the hosted data plane.

Bounded hosted testing

Hosted credentials transit the Worker temporarily. The service does not intentionally persist them; the UI must disclose this before submission.

A better signal, less guesswork

Make API failures easier to understand.

API HealthLab is planned as a focused developer tool: select an intent, run one bounded check, inspect evidence and choose the next action.
